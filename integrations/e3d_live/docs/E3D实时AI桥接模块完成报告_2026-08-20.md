# E3D 实时 AI 桥接模块完成报告

报告日期：2026-08-20<br>
模块位置：`integrations/e3d_live`<br>
当前结论：代码、隔离部署、协议、受控写入门和静态稳定性验证已完成；真实 API 调用与 E3D 写入验收仍须在用户登录 Design 并提供 API Key 后执行。

## 一、建设目标

本次工作为 AVEVA E3D Design 建立一个与项目其他知识、生成器和业务模块隔离的实时 AI 交互接口，使操作者能够直接在指定 E3D 进程中完成以下流程：

1. 实时读取当前选中元素的受限属性快照；
2. 在 E3D 停靠面板中输入自然语言修改指令；
3. 由 AI 生成结构化、可审查的修改预览；
4. 由网关和 E3D Add-in 双重校验修改目标、当前值、作用域和操作类型；
5. 仅在操作者再次确认后执行受控事务；
6. 默认不保存工作，只有明确勾选后才执行 `Save Work`；
7. 记录不含密钥的审计回执。

模块严格绑定一个 E3D 操作系统进程、一个项目、一个 MDB 和一个 Design 模块。其他 E3D 进程即使打开同一项目，也不会自动接入本次会话。

## 二、总体架构

系统由三个隔离层组成：

### 1. E3D x86 Add-in

Add-in 运行在 AVEVA E3D Design 进程内部，负责：

- 捕获 Current Element 变化；
- 读取白名单属性并生成选择快照；
- 显示 AI Provider、模型、API Key、修改指令和返回结果；
- 展示待执行 ChangeSet；
- 在最终确认后调用 AVEVA 数据库接口；
- 使用 Undo Transaction 执行修改；
- 回读属性验证写入结果；
- 任一操作失败时中止整个事务；
- 根据用户明确选择决定是否保存工作。

Python 网关不会持有或跨进程传递 `DbElement`；所有 AVEVA API 调用都留在 E3D UI 线程内。

### 2. 本地回环网关

Python 网关仅监听 `127.0.0.1`，并使用随机会话令牌验证请求。网关负责：

- 校验 E3D 进程 PID；
- 校验项目、MDB、模块作用域；
- 限制消息大小和字段集合；
- 调用本地或外部 AI Provider；
- 对 AI 返回进行严格的本地协议验证；
- 生成短时有效的 ChangeSet；
- 对确认请求进行一次性授权；
- 记录无密钥 JSONL 审计回执；
- 保证重复请求幂等，冲突请求关闭失败。

### 3. AI Provider 适配层

当前保留两个互不替换的 Provider：

| Provider | 调用范式 | 默认模型 | 默认地址 |
|---|---|---|---|
| Token Rhythm | OpenAI-compatible Chat Completions | `deepseek-v4-flash` | `https://tokenrhythm.studio/v1` |
| OpenAI | Responses API + Structured Outputs | `gpt-5.4-2026-03-05` | OpenAI 官方地址 |

Token Rhythm 面板配置已预置地址和默认模型，正常情况下操作者只需要输入 API Key。模型 ID 仍可修改，以适应账户实际可用模型。

## 三、消息与响应协议

协议版本为 `2.0`，采用显式字段和 `additionalProperties: false` 的封闭模式。

主要消息包括：

- `selection_snapshot`：当前元素白名单属性快照；
- `change_preview_request`：选择快照与用户修改指令；
- `configure_assistant`：Provider、模型和仅驻留内存的 API Key；
- `apply_authorization_request`：操作者确认后的精确 ChangeSet 授权请求；
- `apply_result`：E3D 实际执行及回读结果。

AI 不能直接发送任意 PML 或数据库命令。所有 AI 输出必须转换为本地定义的操作对象，并再次验证以下内容：

- 目标元素与 Current Element 完全一致；
- 项目、MDB、模块和 E3D PID 完全一致；
- 预期当前值与 E3D 实时值一致；
- 操作 ID、顺序和数量未发生变化；
- ChangeSet 未过期；
- 属性位于可执行白名单；
- 不存在跨元素修改。

## 四、当前可执行边界

当前允许执行的属性：

- `DESC`
- `XLEN`
- `YLEN`
- `ZLEN`
- `HEIG`
- `DIAM`
- `DTOP`
- `DBOT`

以下能力尚未开放：

- 创建或删除元素；
- 修改名称或所有权；
- 修改目录引用；
- 执行任意 PML；
- 跨元素批量操作；
- 写入位置 `POS` 或方向 `ORI`；
- 未经确认自动保存工作。

这是有意设置的安全边界。空间位置和方向修改需要独立的类型解析、坐标基准和数值几何验证后才能开放。

## 五、API Key 与信息隔离

API Key 采用以下处理方式：

- 在 E3D 面板中使用密码输入框；
- 通过已认证的本机回环会话发送；
- 进入网关后仅保存在进程内存；
- 不写入 PID 会话文件；
- 不写入审计日志；
- 不回显到 E3D 响应框；
- 网关退出后自动消失；
- Provider 重新配置时替换旧密钥并撤销旧预览。

`YOUR_API_KEY`、`sk_xxx` 和 `MODEL_ID` 等示例占位符会被拒绝。Token Rhythm Provider 的地址固定为已配置的 HTTPS 端点，HTTP、内嵌凭据、查询字符串、片段和无关地址均被拒绝。

对外发送的数据只包含：

- 当前作用域；
- 用户指令；
- 当前元素的白名单属性快照。

桥接令牌、会话 ID、仓库记忆、其他项目文件和其他 E3D 进程数据均不会进入 AI 请求。

## 六、稳定性与失败保护

已实现并验证：

- PID 和项目作用域不匹配时拒绝；
- 不支持的字段和属性拒绝；
- 外部 AI 输出目标漂移时拒绝；
- ChangeSet 超时后拒绝；
- 选择元素变化后使待执行 ChangeSet 失效；
- 同一请求 ID 重复提交返回相同结果；
- 同一请求 ID 携带不同内容时关闭失败；
- 并发重复预览在单一执行通道中串行处理，同一请求只调用一次外部模型并只生成一份 ChangeSet；
- Provider 切换时清空旧缓存和待执行 ChangeSet；
- Provider 切换期间仍在运行的旧预览不会注册；
- 健康检查也要求本机会话令牌，未认证请求返回 `401`；
- 网关持有目标 E3D 进程的精确 Windows 进程句柄，原进程退出后自动关闭，避免 PID 被复用后误接管；
- 执行回执必须与原 ChangeSet 的操作顺序、属性、前值、请求值、状态和持久化声明一致；
- 同一结果请求 ID 携带不同回执内容时拒绝，防止终态审计被覆盖；
- 非预期网关异常只返回净化后的固定错误，不把密钥或内部异常文本返回给 E3D；
- 执行前再次读取 E3D 当前属性；
- 执行后回读全部属性；
- 任一写入或回读失败时调用事务回滚；
- 保存工作默认关闭；
- 审计记录不包含 API Key 和桥接令牌；
- 并发选择消息处理不会破坏计数和会话状态。

## 九、操作说明

1. 启动隔离 Monitor 并由操作者本人完成 AVEVA 登录；
2. 进入 Design/Model；
3. 启动绑定目标 `des.exe` PID 的本地网关；
4. 在 `E3D AI Assistant (Controlled)` 面板选择 Provider；
5. API Key 只在 E3D 面板输入，不发送到聊天或写入配置文件；
6. 选择一个测试元素；
7. 输入修改指令并点击 `Preview Changes`；
8. 审查每条属性变更；
9. 只有确认目标和值都正确后才点击 `Apply Verified ChangeSet`；
10. 首次测试不要勾选 `Save Work after verified apply`。

## 十、结论

E3D 实时 AI 桥接模块的代码、协议、Provider 适配、进程隔离、受控写入门、回滚机制、静态测试和隔离部署已经完成。系统已具备在指定 E3D Design 进程中进行“选择读取—自然语言预览—人工确认—受控事务—回读审计”的完整技术链路。

本报告不把尚未发生的真实 API 调用和 E3D 数据库写入描述为已验收。最终生产可用结论应以用户完成上述实机验收清单后的证据为准。
